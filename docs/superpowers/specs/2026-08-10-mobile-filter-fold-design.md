# 모바일 필터 접기 — 상단 크롬 122px → 62px

2026-08-10. OPEN-DECISIONS #2의 실행. 사용자 결정(2026-08-07): 모바일에서
카테고리 알약을 필터 시트로 접고 무드 레일만 상시 노출.

## 문제

390px에서 카테고리 알약 줄(60px) + 무드 레일(62px) = 크롬 122px, 가로 스크롤 두 줄.
무드가 탐색의 주축인데 카테고리가 같은 자리에서 경쟁한다. 정렬·저장만 보기는
모바일에서 아예 숨겨져 기능이 죽어 있었다.

## 설계

### 트리거 — 무드 레일 오른쪽 끝 고정 버튼 (모바일 전용)

- `.explore-layout` 안에 절대 배치로 무드 레일 우측 상단에 겹침. 레일 목록은 그 아래로 스크롤.
- `<details className="filter-menu">` — 헤더 지역 메뉴(`.area-menu`)와 같은 네이티브
  disclosure 패턴 재사용. 새 상태 관리 없음.
- summary 내용: "필터" 레이블 + 활성 필터가 「전체」가 아니면 그 이름 표시 (예: 「필터 · 무료」).
  활성 표시가 곧 배지라 별도 dot 불필요.
- 761px 이상에서는 `display: none` — 데스크톱 무변화.

### 패널 — 헤더 아래 고정, 지역 메뉴 모바일 CSS 미러

- `position: fixed; top: var(--header-height); left/right: 0` — `.area-menu__panel`
  모바일 규칙과 동일한 자리·질감.
- 내용물: 기존 `<FilterBar>` 컴포넌트 그대로 (알약이 패널 안에서 랩됨) +
  모바일에서 죽어 있던 `저장만 보기` 버튼과 정렬 `<select>`를 패널 하단에 복원.
- 필터를 고르면 패널이 닫힌다 (`detailsRef.removeAttribute("open")`).
  정렬·저장만 보기는 켜고 끄는 조작이라 닫지 않는다.

### 크롬 회수

- ≤760px에서 `.explore-toolbar`를 통째로 숨김 (모바일에선 필터바만 담고 있었음).
- `.explore-layout`의 `padding-top: 60px`(≤1100px, 떠 있는 툴바 자리)는
  ≤760px에서 0으로 — 무드 레일이 첫 줄이 된다.
- `.explore-map-actions { top: 126px }` → 레일 아래 여백에 맞게 축소 (~74px).
- 761~1100px(태블릿)는 현행 유지 — 툴바가 보이므로 padding도 유지.

## 하지 않는 것

- 카테고리 자체 제거(결정 시 대안 2안) — 접기만 한다.
- 새 분기점 — 760px만 쓴다. 새 의존성 없음.
- FilterBar 컴포넌트 수정 — 호출부에서 감싸기만.

## 검증

- 390px: 크롬 실측 122px → 62px대, 가로 스크롤 줄 2 → 1.
- 패널 열기 → 필터 선택 → 닫힘 + 목록 반영. 정렬 변경은 패널 유지.
- 761px·1100px·1440px에서 시각 무변화 (스크린샷 대조).
